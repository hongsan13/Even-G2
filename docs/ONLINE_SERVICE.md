# オンライン管理版（v0.4.0）

利用者がODPT登録・トークン入力・GTFS取込をしなくても、駅とルートを選んで案内を取得するための構成。**v0.4.1の公開先はhttps://transit-hud.onrender.com。** 実HTTPSで駅取得と検索を確認済み。v0.4.1の配布物は接続先入り。以前のサーバーをManual Deployで更新してから使用する。実機は未検証。

## 構成と提供範囲

- 運用者：Dockerサーバーを配置し、利用可能な事業者とODPTトークンをホスティングの環境変数/シークレット管理画面で設定。
- 利用者：接続先を埋め込んだHubビルドを起動。駅一覧は自動取得し、通常画面はルート選択・案内中心。既存の取込/認証設定は詳細設定へ折りたたむ。オンライン駅一覧は端末取込時刻表と別の保存キーを使い、以前取り込んだデータを上書きしない。お気に入りは維持するが、配信対象外の駅IDは再選択が必要。
- 時刻表：サーバーメモリに保持し、約1日ごとに更新。起動時の都営は公式取得失敗時に同梱CC BYデータへ戻る。最後の正常取得から48時間、ダイヤ有効期間、許諾期間のうち先に来る制限を超えたデータを新規検索に使わない。
- API：駅/路線の参照一覧と、現在時刻で検索した少数の案内だけを返す。ZIP・全便JSON・カレンダー全件・任意日付の一括取得エンドポイントは提供しない。
- 検索：最大2回乗換、過去60分の乗車便ロックに対応。2件まで並行Workerで検索し、20秒で打ち切る。検索結果は最大7経路（未来の推奨/候補と過去の便）、60秒の期限付き。
- Realtimeはサーバー版に未接続。案内は予定時刻。完全な全国鉄道・新幹線対応や、多人数同時利用時の性能保証ではない。
- 端末には駅一覧・お気に入りを保存し、認証時刻表全体を配らない。このモードの**新規検索には通信が必要**。ロック済み便の予定案内はメモリ上で継続する。従来のローカル取込モードのオフライン検索とは異なる。

## ODPTの利用条件

2026-10-16に公式開発者サイトの規約・開発者ガイドラインを確認。アプリ公開についての記載がある一方、基本/限定ライセンスとも、第三者が再利用可能な状態でのデータ・複製物・復元可能な派生データの公開/再配布などに制限がある。

- [公式規約・基本ライセンス](https://developer.odpt.org/terms)
- [公式ドキュメント・開発者ガイドライン](https://developer.odpt.org/documents)
- [チャレンジ限定ライセンス](https://developer.odpt.org/challenge_license)

経路案内APIなら無条件に公開できると断定していない。駅/路線一覧、経路回答、サーバー保持期間を含め、自分の登録・参加資格で一般利用者へ提供できるかを確認してから認証事業者を有効にする。公開元表記・精度の非保証・問い合わせ先をアプリに表示する。JRなどの限定データには2027-03-12までの期間制限があり、早期終了時は運用者が該当事業者を外す。キーを共用利用者へ渡す方式ではない。

初期設定は**都営公開データのみ**。認証事業者はキーを入れるだけでは有効にならず、`ODPT_SERVICE_TERMS_CONFIRMED=true`も必要。これは利用許諾の自動判定や許諾取得の代わりではない。実際の認証取得・一般公開の利用条件確認・実機検証は未完了。

## 初めての配置はRender設定を使う

[初心者向けの操作手順](RENDER_SETUP.md)と[配置開始リンク](https://render.com/deploy?repo=https://github.com/hongsan13/Even-G2)を用意しました。RenderはNode.jsの標準実行環境を使い、Dockerイメージを自分で作らずに配置できます。Docker構成も引き続き使えます。Render上では発行された自身のURLを管理用originに自動追加するため、最初のサーバー起動にHubのorigin入力は不要です。v0.4.1では公開案内APIだけ匿名クライアント向けCORSを許可し、管理APIは自身のURLなど明示originに限定します。無料構成は休止があり試用向けです。

## Dockerで起動

Node.js 24、npm、Dockerを用意する。キーはチャット・GitHub・イメージのビルド引数へ入れない。

```sh
npm ci
npm run server:build
docker build -f Dockerfile.runtime -t transit-hud-service:0.4.0 .
```

このruntimeイメージは非rootユーザーで実行し、ビルド済みのNode.jsサーバーと公開都営データだけを含む。外部npmダウンロードを行わないruntime Dockerビルド/起動/実検索を検証済み。通常の`Dockerfile`はソースからnpm ciとビルドを行うmulti-stage版で、このクラウドでは依存取得が完了せず停止したため全体ビルドは未検証。

ローカルの公開データで試す例：

```sh
docker run --rm -p 127.0.0.1:8080:8080 \
  -e TRANSIT_ALLOWED_ORIGINS=http://127.0.0.1:4194 \
  -e TRANSIT_FEEDS=toei \
  transit-hud-service:0.4.0
```

これはローカル検証用。公開時はDocker対応ホストへ配置し、HTTPS終端・再起動・ホスト側の帯域/リクエスト制限を設定する。`PORT`の初期値は8080。健康確認は`/healthz`。ヘルスの成功と配布元の取得成功は別で、後者は管理状態と実際の検索で確認する。

設定値の例は[server/env.example](../server/env.example)。実値は運用先の管理画面へ入力する。

| 設定名 | 用途 |
|---|---|
| `TRANSIT_ALLOWED_ORIGINS` | 管理画面/APIの正確なoriginをカンマ区切り。明示設定がない場合はブラウザ接続を許可しない。Render上は自身の発行URLを自動追加する。`*`にしない。公開の駅一覧・検索APIはv0.4.1で別の公開CORSを使用する。ローカル検証用originを本番へ持ち込まない。 |
| `TRANSIT_FEEDS` | `toei`など最大16配布元。初期値は`toei`。`kanto`で関東10配布元を選択。 |
| `ODPT_KEY` | 通常ODPTトークン。ホストのシークレット設定へ。 |
| `ODPT_CHALLENGE_KEY` | チャレンジ専用トークン。参加条件・許諾期間を確認する。 |
| `ODPT_SERVICE_TERMS_CONFIRMED` | 運用者が一般利用者向けの利用条件を確認した場合のみ`true`。初期値は無効。 |
| `TRANSIT_ADMIN_TOKEN` | 管理状態確認/更新用の独立した秘密。ODPTトークンを流用しない。未設定なら管理APIは利用不可。 |

認証事業者のID：`auth-JR-East`、`auth-Keio`、`auth-Sotetsu`、`auth-Tobu`、`auth-TokyoMetro`、`auth-MIR`、`auth-TWR`、`auth-TamaMonorail`。大きな事業者を同時に選ぶと既存の40,000便/10,000駅制限に達する場合がある。事業者間の徒歩乗換の自動生成は未実装。サーバー版へ端末の手動乗換設定は同期しない。

サーバーは要求本文・トークン・利用者のルートをログ/DBへ記録しない。IPアドレスによる簡易制限はメモリ上の1分窓で、1接続元120要求/分。リバースプロキシ越しでは接続元が共有されるため、ホスト側の制限と合わせて運用する。これは認証基盤や大規模配信対策の代わりではない。CORSもアプリの正規性を証明する仕組みではない。運用先が保存するアクセスログ、保存期間、公開運営者連絡先は公開前に確定する。

## 公開APIと管理APIの分離（v0.4.1）

`/v1/catalog`と`/v1/journeys`だけは、Hub WebViewのopaque originを含む匿名のブラウザクライアント向けに`Access-Control-Allow-Origin: *`を返す。credentialsは許可せず、Authorizationヘッダーも公開プリフライトで許可しない。時刻表全件/認証鍵は返さず、元々認証なしで提供していた駅参照・少数の案内をブラウザから利用可能にするための変更。CORSは利用者認証ではない。

`/admin`、`/admin/status`、`/admin/refresh`等には公開CORSを適用しない。明示originと管理トークンの要件を維持する。`TRANSIT_PUBLIC_API=false`で公開APIも従来のorigin制限に戻せるが、これ自体は認証やアクセス制御の代わりではない。Render側のコード更新が反映されるまではHubからの案内取得は拒否される。

## オンライン管理

HTTPSの公開先に配置したら、同じoriginの`/admin`を開く。管理トークンを入力すると事業者の状態確認と公式時刻表の更新ができる。入力した管理トークンはページ内だけで使い、ブラウザストレージへ保存しない。更新操作は最低60秒間隔。

ODPTトークンや有効な事業者の変更は、運用先のシークレット/環境変数設定画面で行い、サーバーを再起動する。認証情報を配る利用者向けの管理画面ではない。サーバーキャッシュは再起動で消え、必要なデータを再取得する。

## Hub用ビルド

公開先のHTTPS originが確定してから実行する。例のドメインは置き換える。

```sh
TRANSIT_SERVICE_URL=https://YOUR-SERVICE-ORIGIN npm run pack
```

これにより接続先をビルドへ固定し、CSPとパッケージのnetwork whitelistへそのoriginを追加する。認証鍵は入れない。任意URLを利用者に入力させない。生成された`.ehpk`を同じHubプロジェクトへアップロードする。公開先が未定の状態の標準配布物ではオンライン版は有効にならない。

**まだ必要な作業：** Renderへ最新コードを反映、Hubへv0.4.1アップロード、G2実機通信・操作確認。認証事業者を追加する場合はODPTキーをホストのシークレットへ設定し、提供許諾を確認。その後に一般公開を判断する。
