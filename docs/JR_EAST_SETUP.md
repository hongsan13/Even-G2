# JR東日本の時刻表を使う最短手順（2026-10-22）

首都圏のJRを取り込む処理は実装済みです。現在確認できる公式配信はJR東日本の関東一部路線で、首都圏の全路線を網羅すると保証できるものではありません。

ユーザーの現在の取得状況は「通常ODPTトークンのみ」。このJR配信には別のチャレンジ専用トークンが必要です。通常トークンのままではJRの取得を開始しません。

## 操作

1. [ODPT開発者サイトのチャレンジ案内](https://developer.odpt.org/challengeinfo)で参加条件を確認し、ログインしたアカウントで参加登録。専用トークンを取得します。
2. Renderの既存サービス → Environmentで `ODPT_CHALLENGE_KEY` を追加し、その値を秘密情報として保存。メトロ用の `ODPT_KEY` は残します。
3. `TRANSIT_FEEDS` が `kanto` ならJRも選択済みです。それ以外なら既存リストへ `auth-JR-East` を追加します。都営・メトロとJRだけなら `toei,auth-TokyoMetro,auth-JR-East`。
4. 自分のアプリでの提供条件を確認済みの `ODPT_SERVICE_TERMS_CONFIRMED=true` を維持し、Save, rebuild, and deployで再配置。
5. Live後に管理画面で「公式時刻表を更新」。「JR東日本」が利用可能になったらHubを閉じて開き直します。Hubへのトークン入力やファイルの再取込は不要です。

管理画面用の `TRANSIT_ADMIN_TOKEN`、通常ODPTの `ODPT_KEY`、チャレンジ専用の `ODPT_CHALLENGE_KEY` は別です。値をチャットやGitHubへ貼る必要はありません。

## 実装と確認状況

- `auth-JR-East` の認証付きGTFS取得・定期更新・読込・サーバー経路検索は実装済み。
- GTFS以外にも路線別の公式TrainTimetable JSONを取り込む実装があります。同じチャレンジ専用トークンが必要です。GTFSが取得できない場合の手段であり、専用トークン不要の手段ではありません。
- 2026-10-22に[JR東日本の公式JSONカタログ](https://ckan.odpt.org/dataset/jreast__r_train_timetable/resource/5df12c9e-c840-4d5f-8222-05be1d7a8a18)で「関東エリアの一部路線」、チャレンジAPI、限定ライセンスの記載を再確認。
- この実行環境には専用鍵・Render認証がないため、JRの実時刻表取得や本番設定変更はしていません。今回の公開サーバー取得はタイムアウト。開発者サイトはHTMLのJS起動ページまで取得できましたが、クラウドChromiumはTLS証明書エラーで画面確認できず、未確認のボタン名や登録画面の操作を断定しません。
- JR実データがまだないため、架空の時刻表や所要時間を作って公開する変更はしていません。新しい.ehpkも不要で再生成していません。

条件に合うJR配信を使えない場合、広範囲の正規経路API（駅すぱあと等）の契約が別の候補です。料金やG2表示条件は確認が必要で、自動契約はしません。
